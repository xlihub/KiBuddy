# Ki 产品采用独立发布节奏

Ki-Model、Ki-Core 与 Ki-Buddy 根据自身产品计划决定发布时间和版本号。aionrs、AionCore 与 AionUi 的完整正式版本分别只形成上游候选版本；管理员在准备 Ki 产品版本时明确选择新的发布基准或继续使用当前基准，选择新基准后才创建同步 PR。这样可以避免上游的高频发布直接决定 Ki 的维护节奏，同时保留按产品需要采用上游变化的能力。

## Considered Options

- 上游发布后立即同步和发布 Ki 版本：会让 Ki 的节奏受上游频率控制。
- 固定延迟一周同步：时间阈值不能表达产品是否准备好接受该版本。
- 在 Ki 版本准备时选择发布基准：由管理员结合产品计划和累计变化作出决定。

## Consequences

- Ki 可以跳过中间上游版本，采用目标基准时必须审查并记录累计变化。
- 检测到上游候选版本不会自动创建同步 PR。
- 同步 PR 不得自动合并；发布基准和 Ki 目标版本由管理员确认。

2026-09-11：用户确认上述原则同样适用于 Ki-Model。新的 Ki-Model 正式版本只形成 Ki-Core 的可选 SDK 依赖，不自动修改 Core pin 或触发下游发布；具体治理与发布机制见 ADR 0016。
